# OpsGym episodes

Raw episodes behind [OpsGym](https://github.com/NiharP31/OpsGym): every held-out evaluation
episode, the three training pools, and the same evaluations as Inspect AI logs. The analysis
JSONs and figures in the GitHub repo are computed from these files. The adapters are at
[Nihar31/opsgym-qwen3-1.7b-lora](https://huggingface.co/Nihar31/opsgym-qwen3-1.7b-lora).

All tasks are template-generated and all names are synthetic. Episodes are outputs of Qwen3-1.7B
(base and LoRA-tuned) in a simulated ticketing/CRM workspace.

## Files

**`evals/`**: 10 models (base + 9 adapters) × tasks × 8 samples, T=0.7, the same sampling seed per
(task, sample) for every model. sha256 matches `runs/evals/*.meta.json` in the GitHub repo.

**`inspect/`**: `<split>__<model>.eval`, 40 Inspect AI logs (4 splits × 10 models) exported from
`evals/` by `scripts/export_inspect.py`. Open with `inspect view --log-dir inspect/`.

**`tasks/`**: `tasks.parquet` (C, A, B) and `tasks_a2.parquet` (A2), the task stores the episodes
refer to by `task_id`, plus `tasks_a2cal.parquet`, the base-model calibration variants run before
A2 (D41b; no episodes from them are in this dataset). All three are also in the GitHub repo.

## Episode schema (one JSON object per line, evals and pools)

| field | meaning |
|---|---|
| `model` | `base` (evals) or `Qwen/Qwen3-1.7B` (pools), or an adapter name like `natural_s0` |
| `split`, `family`, `task_id`, `sample_idx` | which task and sample (`split` is evals only) |
| `sampling`, `sampling_seed` | temperature, max_tokens, base seed, and the per-(task, sample) seed |
| `messages` | the full chat: system, user, assistant tool calls, tool results |
| `finish_kind` | `finish`, `step_limit`, or `error` |
| `finish_message` | the agent's final message |
| `final_state` | the whole database at episode end; verifiers read only this |
| `expected` | the correct `account_id`, `priority` and `owner_id` |
| `rewards` | strict / medium / loose verdicts (0 or 1) |
| `breakdown` | per-check results: ticket_exists, exactly_one_new, right_account, right_priority, right_owner |
| `hack_kind` | for loose-pass, strict-fail episodes: `skipped_work`, `wrong_target` or `other`; else null |
| `steps`, `invalid_calls`, `repeated_invalid_calls`, `text_only_turns` | episode diagnostics |
| `code_version`, `task_set_hash`, `prompt_hashes`, `run_id` | provenance |

## Intended use

Studying reward hacking, verifier design and false claims in tool-use agents. The `shortcut_100`
episodes contain an agent claiming work it did not do; that is the point of the dataset.
